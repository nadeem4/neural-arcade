# Neural Arcade

Small browser games where tiny neural networks learn in front of you; each game teaches one machine learning idea.

## Commands
- Setup: npm install
- Test: npm test (Vitest; runner-presets takes ~90 s)
- Run: npm run dev (serves http://localhost:4173)

## Layout
- assets/games.js: the one config: every game (page, write-up, category, optional youtube id, optional `uses` list of concept ids), every category and the CONCEPTS (shared words)
- assets/: shared code and styles (share.png is the default share banner): studio.css (tokens, shared styles, video facade), site.js (header/footer), game.css + game-page.js (game page), home.js, browse.js, category.js, concepts.js, concept-page.js (shared concept page builders), grid.js (shared grid world for the RL concept pages), concept.css, story-page.js, video.js, theme.js, fonts/
- index.html, about/, concepts/, games/index.html, category/: home, About, Concepts (assets/concepts.js), browse and category pages
- games/<name>/: one game each (index.html, share.png, sim.js, ai.js, tune.js, main.js, words.js, story-data.js, story.json (generated by story-data.js), record.js (maze only: headless clip recorder for the concept videos), demo.js (home demo, if it has a video), art/ (CC0 sprite sheets, if it has art), how-it-works/)
- concepts/<id>/: one page per concept, all eight (pid, agent, state-action-reward, return, policy, value, mdp, reward-design), linked from every chip and the Concepts list: index.html (playground, tries, write-up, video, games, related), sim.js (pure logic), play.js (playground and presets), figures.js (the six RL pages; pid and reward-design have fig-*.webp stills instead), share.png (pid and reward-design; the others use assets/share.png); policy also has rulebooks.js (its three example rulebooks)
- games/city/ (Reward City): chicago.json (generated, never hand-edited), sim.js, train.js, presets.js (the tuned values every slice uses), playback.js (taxi route frames, lights, chase camera maths), events.js (tripEvents: what each step of a trip did, and the floating tags), drive.js (smooth eased driving with turns and stops), director.js (camera phases: map, swoop, chase, pullback), meter.js (live reward meter), minimap.js (round minimap model and draw), sound.js (WebAudio blips, mute and reduced motion), receipt.js, words.js, jobs.js (newest-job-wins guard, main-thread fallback), worker.js (training Web Worker), story-data.js + story.json (seeded story recording, generated) + story-model.js (figure draw lists), reward.js (the six reward lines, the Reset defaults, try count), rates.js (rate card stepping and display rows), screens.js (map, training, driving, done state machine), endcard.js (what the end card shows), garage.js (up to four kept taxis, saved in localStorage `rc-garage-v1`), naming.js (taxi names, notes and rate chips), garage-view.js (the garage drawer, with a Race toggle on each taxi), race.js (race clock, winner, banner text), race-view.js (race meters, banner), stage.js (Stage interface and the no-WebGL fallback), geometry.js (map vectors to typed arrays), scene.js + scene-math.js (the 3D stage, drag to turn; camera clamps and colours), scene-taxi.js + taxi-model.js (the taxi as box parts, brake lamps), scene-look.js + sky.js (sky gradient, fog, lit windows, heat fade; pure parts in sky.js), signals.js (signal state for the taxi heading, lamp corners), vendor/ (pinned three.js r160 and its licence), main.js (page wiring), city.css (page, rate card, bottom bar, end card, phone sheets), index.html, share.png + shot.jpg (a page screenshot), how-it-works/; scripts/city/: fetch-overpass.mjs, convert.js (OSM export to grid), chicago.config.json, spike.mjs (the five-card gate), data/ (git-ignored Overpass export)
- games/treasure-room/ (Treasure Room): sim.js (room, step with slip, value, policy, return), levels.js (the six levels and ?level= routing), words.js; more files land in later slices
- engine/: shared learning code (tinynet, evolve, reinforce, qlearn, train, brain-panel, curve)
- videos/<game>/: git-ignored upload pack per explainer video (mp4, captions, description, thumbnail)
- tests/: Vitest tests for the engine, each game's sim, words and story, the games config and page markup

## Conventions
- Every page carries share/SEO tags (canonical, og:*, twitter:*) hard-coded in its HTML; a game banner is games/<name>/share.png (1280x720), copied from its video thumbnail, or its shot.jpg if it has no video; assets/share.png is the site default
- No build step: plain HTML, CSS and ES modules; deployed as static files to Vercel
- Every page links assets/studio.css; game pages add game.css and a game-only file, How it works pages add assets/story.css (and a story.css of their own if they need one); concept pages add assets/concept.css and carry share tags like any page. Adding a youtube id to assets/games.js, and copying its thumbnail to games/<name>/share.png, is all a video needs
- A game with a video also gets a `demo` block in assets/games.js (net, learns, panel, alt words) and a games/<name>/demo.js exporting `startDemo(canvas, panelEl)`, so it can be the home hero: the home page picks the newest game with a youtube id and a demo, and its stage words and recorded run come from those, with no home-page code change
- Every game has a brief, (i) buttons, an illustrated How it works write-up and one stated lesson; no tours or quizzes; one optional narrated explainer video per game, hosted on YouTube, shown as a click-to-play facade (assets/video.js)
- How it works figures come from a seeded run recorded by story-data.js; regenerate it when the sim changes
- Plans and design docs go in Notion, never git (docs/ is ignored)
