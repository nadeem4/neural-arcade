# Neural Arcade

Small browser games where tiny neural networks learn in front of you; each game teaches one machine learning idea.

## Commands
- Setup: npm install
- Test: npm test (Vitest; runner-presets takes ~90 s)
- Run: npm run dev (serves http://localhost:4173)
- Pages: `npm run pages` rewrites the generated pages (the three `<track id>/index.html` and `concepts/<id>/index.html` for the six Treasure Room lessons) from assets/tracks/; `node scripts/build-pages.mjs --check` exits 1 if any differ (a test also checks this)
- Record Reward City footage: open `/games/city/?record=1&card=<preset id>&fps=<n>&cam=<default|map|auto>&endcard=1&maxms=<n>` (frame-stepped through `window.__rc`; see README)

- index.html, about/, concepts/, games/index.html, category/: home, About, Concepts (assets/concepts.js), browse and category pages

- concepts/<id>/: one page per concept, all eight (pid, agent, state-action-reward, return, policy, value, mdp, reward-design), linked from every chip and the Concepts list: index.html (pid and reward-design: hand-written, with playground, tries, write-up, video, games, related; the other six, the Treasure Room lessons, have a generated index.html, never hand-edited, built from the track config plus writeup.html (the playground-and-tries section and the write-up section) and page.js (the playground, figure and tries wiring)), sim.js (pure logic), play.js (playground and presets), figures.js (the six RL pages; pid and reward-design have fig-*.webp stills instead), share.png (pid and reward-design; the others use assets/share.png); policy also has rulebooks.js (its three example rulebooks)

## Conventions
- Adding a Treasure Room lesson: add the lesson (with its `level`, status live) to assets/tracks/reinforcement-learning.js, add `concepts/<id>/` with sim.js, play.js, figures.js, writeup.html and page.js (copy a finished one), then run `npm run pages`; lesson pages load studio.css, game.css, treasure-room.css, concept.css and lesson.css (lesson.css guards the concept playground against the first three's leaks, so do not edit game.css or treasure-room.css for lesson pages); the page gets the playable level, Mark as done, video slot ("Video coming soon" while `video` is null), In the wild and previous/next from config. One level per page (the panel's element ids are page-wide)
- Every page carries share/SEO tags (canonical, og:*, twitter:*) hard-coded in its HTML; a game banner is games/<name>/share.png (1280x720), copied from its video thumbnail, or its shot.jpg if it has no video; assets/share.png is the site default
- No build step: plain HTML, CSS and ES modules; deployed as static files to Vercel
- Every page links assets/studio.css; game pages add game.css and a game-only file, How it works pages add assets/story.css (and a story.css of their own if they need one); concept pages add assets/concept.css and carry share tags like any page. Adding a youtube id to assets/games.js, and copying its thumbnail to games/<name>/share.png, is all a video needs
- A game with a video also gets a `demo` block in assets/games.js (net, learns, panel, alt words) and a games/<name>/demo.js exporting `startDemo(canvas, panelEl)`, so it can be the home hero: the home page picks the newest game with a youtube id and a demo, and its stage words and recorded run come from those, with no home-page code change
- Every game has a brief, (i) buttons, an illustrated How it works write-up and one stated lesson; no tours or quizzes; one optional narrated explainer video per game, hosted on YouTube, shown as a click-to-play facade (assets/video.js)
- How it works figures come from a seeded run recorded by story-data.js; regenerate it when the sim changes
- Plans and design docs go in Notion, never git (docs/ is ignored)
